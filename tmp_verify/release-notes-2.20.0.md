发布: v2.20.0

版本号 2.19.1 → 2.20.0（package.json / app.json / build.gradle 三处同步；
package.json 此前滞后在 2.17.0，一并修正）。versionCode 1 → 20。

本版主要内容（详见各条提交）：

修复
- 测试从未跑起来：缺 babel/jest 配置，4 个套件全部解析失败。补配置后既有用例全通
- 类型系统失效：源码 80 个错误清零；notableEvents 声明为 string[] 却按对象用，
  导致谣言/情绪/章节/记忆/背景互动 5 个子系统长期静默失效
- 缓存 token 兜底双重计费：miss 缺失时取全量输入，命中部分被算两次
- 2 跳谣言被 off-by-epsilon 滤掉（certainty 恰好等于阈值 0.2）
- HTTP 错误被掩埋成「网络连接失败」；非流式调用耗时恒为 ~0ms
- 并发下归因串味（全局标签栈 + Promise.all）
- 多处会崩的调用：showAlert 缺参、不存在的 saveChapter、const 重新赋值等

架构
- 接上写完全未接线的 JSONL 存储层（原先每轮全量覆盖，O(n²)）
- 会话状态从 useState + 8 个手工同步 ref 迁到单一 store；pipeline 内 0 ref
- stage8 同步阶段收敛为单次提交，消除半提交

性能
- 角色推演 N 次请求 → 1 次（实测 8 角色：8 → 1）
- 抛光改非阻塞；单轮请求数 8 → 2
- 开启 R8：APK 32.3MB → 27.5MB（dex 7.53 → 3.10MB）

可观测性
- 11 处 AI 调用全部按子系统归因；设置页新增「调用诊断」
- 叙事自检（开发期）：抓凭空造角色、回响未被使用、情绪没演出来

体验（静默世界）
- 接通 NPC 知识渠道（原先 NPC 的知识被算出来却从不注入）
- 信息传播按轮次门控，谣言这才真的会"传"
- 往事回响：事件按概率埋下，3~8 轮后以别的形式浮现

定价
- 更新至官方 2026 峰谷价（空闲价 = 高峰价的一半；高峰为北京时间
  周一至周五 9-12、14-18）；模型名改为 deepseek-flash

验证
- tsc 0 错误；jest 23 套件 267 用例
- 真机（vivo V2425A / Android 16）全流程跑通

未验证
- 回响需 3~8 轮才浮现，真机只跑了 5 轮，未实际观察到一条回响走完
  "埋下→浮现"并改变 AI 输出的过程（机制有单元与集成测试覆盖）
